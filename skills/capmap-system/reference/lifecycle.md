# 生命周期（闭环说明）

## 各阶段「产物是什么」

| 阶段 | 输入 | 产物 | 谁消费 |
|------|------|------|--------|
| 方案 | 需求/评审 | 方案 md + 变更记录 | 开发、评审 |
| 开发 | 已确认方案 + 代码任务 | **代码** + 底图 §1/§2 + **方案 Tag `开发中`→`已开发`** | 测试、运维、后人 |
| 测试 | 已开发能力 | 测试文档 + 方案/测试 Tag | 发布决策、回归 |
| 规范 | 稳定契约 | `规范/` + 方案 Tag `落地中`→`已落地` | 接入方、运维、前端 |
| 归档 | 闭环结束的方案 | `_archive` + 方案 Tag `已归档` | 考古 |
| 反补 | git 历史 | 底图 §4/§5（正文，无状态 Tag） | 策展人 |

## 进度挂在哪

| 问题 | 看哪里 |
|------|--------|
| 哪些**方案**在开发 / 验证 / 落地？ | 方案文 `状态/*`（Obsidian：`tag:#状态/开发中 tag:#方案`） |
| 某主题有哪些能力、代码在哪？ | 能力底图 §1 / §2（底图**无**状态 Tag） |
| 某次测试跑到哪了？ | 测试文 `测试中` / `已验证` |

## 方案主状态

```text
方案中 → 已确认 → 开发中 → 已开发 → 验证中 → 已验证 → 落地中 → 已落地 → 已归档
```

### 硬约束：禁止跳步

- **验证门**：未 `已验证`（测试通过或测试文明示免测）之前，**禁止** `落地中` / `已落地`。
- **测试文仍为 `测试中`** 时，方案禁止落地态。
- 详情与反例：[status-tags](status-tags.md)「硬约束：主状态禁止跳步」。
- `capmap-lint` 对违规报 `status_skip` error。

## 典型顺序

1. `capmap-scheme`：`方案中` → 评审通过 **`已确认`**  
2. 开干编码：方案 → **`开发中`**；合入后 `capmap-dev`：§1/§2 + 方案 → **`已开发`**（止步于此，不标已落地）  
3. `capmap-test`：测试文 **`测试中`**；方案 **`验证中`** → 通过则双方 **`已验证`**  
4. `capmap-norm`：仅已验证后 → 方案 **`落地中`** → **`已落地`**  
5. `capmap-archive`：方案 → **`已归档`**  
6. 随时 `capmap-backfill`（只改底图正文）

## 冻结与增量版本

方案进入 **`已归档`** 后正文冻结。新需求开 Vn（新文 `方案中`），基线不回迁。
