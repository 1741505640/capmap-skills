# 状态 Tag（Obsidian）

用于在 Obsidian Tags 面板 / 搜索中**快速筛选**进度。

- **筛「哪些方案在开发/落地」** → 看**方案文**的 `状态/*`（一个方案一个主状态）。
- **能力底图**：只打类型 tag `能力底图`，**禁止** `状态/*`。能力清单仍写在正文 §1 表（策展用），不投影到 YAML Tag。
- **测试文**：`测试中` / `已验证`，与方案主状态可并行（方案可同为 `验证中`）。
- **切片文**（大需求）：类型 `切片` + 切片轨状态；进度不占用方案主状态「第几票」。
- **体量**：`已确认` 及之后方案须有且仅有一个 `体量/小` 或 `体量/大`。

## 方案主状态（类型 tag `方案`）

### 小需求

```text
方案中 → 已确认 → 开发中 → 已开发 → 验证中 → 已验证 → 落地中 → 已落地 → 已归档
```

### 大需求（在已确认后插入规格/拆分）

```text
方案中 → 已确认 → 规格中 → 已拆分 → 开发中 → 已开发 → 验证中 → 已验证 → 落地中 → 已落地 → 已归档
```

| Tag | 体量 | 含义 |
|-----|------|------|
| `状态/方案中` | 共用 | 起草 / 评审 / grilling |
| `状态/已确认` | 共用 | 决策收口；已有体量 Tag |
| `状态/规格中` | **仅大** | 写执行规格（seams、范围、不做项） |
| `状态/已拆分` | **仅大** | 切片清单 + 依赖边已人工确认 |
| `状态/开发中` | 共用 | 编码进行中（大：切片未全部验收） |
| `状态/已开发` | 共用 | 方案范围已落地 + §2 已对齐（Agent 对照方案判定，**不**等人测）；大：切片全 `已验收` |
| `状态/验证中` | 共用 | 测试执行中 |
| `状态/已验证` | 共用 | 测试通过或明示免测 |
| `状态/落地中` | 共用 | 规范撰写 / 挂链中 |
| `状态/已落地` | 共用 | 规范已挂 §3 |
| `状态/已归档` | 共用 | 已进 `_archive` |

活跃方案禁止 `已归档`；归档文必须 `已归档`。

### 体量 Tag

| Tag | 含义 |
|-----|------|
| `体量/小` | 一窗可完成；禁止进入 `规格中` / `已拆分`；无 `切片/<方案stem>/` |
| `体量/大` | 须经 `规格中`→`已拆分`；有 `切片/<方案stem>/`；全切片验收后才 `已开发` |

升 `已确认` 时：Agent **先建议体量并说明理由**，**询问用户是否可行**，确认后再写入。禁止静默自定。

## 切片轨（类型 tag `切片`）

```text
待开发 → 开发中 → 待验收 → 已验收
```

| Tag | 含义 |
|-----|------|
| `状态/待开发` | 依赖未齐，或已齐尚未被用户点名领取 |
| `状态/开发中` | 本切片一窗编码中（frontier 内可与其它切片并行） |
| `状态/待验收` | 已交票（须含 Demo 步骤 + 自测摘要），等人确认 |
| `状态/已验收` | 人确认通过；解除下游 `Blocked by` |

切片依赖 = **DAG**（`Blocked by`）。**frontier** = 全部 blocker 已验收（或无 blocker）且自身为 `待开发` 的集合。仅用户点名后才开跑；`capmap-slice` 可推荐运行模式但禁止主动开跑。

## 测试轨（类型 tag `测试`）

```text
测试中 → 已验证
```

## 能力底图（类型 tag `能力底图`）

仅 `tags: [能力底图]`。§1 表可写能力状态字面，**不**进 YAML Tag。

### 硬约束：主状态禁止跳步（尤其验证门）

**Agent / 人改 Tag 时必须遵守，capmap-lint 会拦。**

1. **只能沿合法链条前进**，禁止从靠前状态直接跳到靠后状态。
2. **小需求**：禁止 `规格中` / `已拆分`。
3. **大需求**：禁止 `已确认` → `开发中`（须经 `规格中`→`已拆分`）；未全切片 `已验收` 禁止 `已开发`。
4. **验证门不可跳过**：进入 `落地中` / `已落地` 之前，方案必须已是 **`已验证`**。
5. **测试未通过禁止落地**：若对应测试文仍为 `状态/测试中`，方案**禁止**标 `落地中` / `已落地`。
6. **免测唯一例外**：用户明示免测时，须在测试文结论写明「免测」范围与日期，并将测试文标为 `已验证` 后，方案才可继续。
7. **切片**：禁止领取非 frontier；`待验收` 缺 Demo/自测摘要不得标；`待验收`→`已验收` 仅人；触及重叠不得同时 `开发中`；`Blocked by` 禁止成环。
8. 允许的「合并」仅限相邻且语义重合的两步（例如无独立规范时 `已验证` 可与 `已落地` **同回合**合并，但仍须先满足已验证）。禁止用「合并」跳过测试或大需求规格/拆分。

反例（禁止）：

- 代码写完 → 直接 `已落地`
- 大需求 `已确认` → 直接 `开发中`
- 切片未全验收 → 方案 `已开发`
- 口头一句无 Demo/自测 → 切片 `已验收`

## 文首 YAML

```yaml
---
tags:
  - 方案          # 或 测试 / 能力底图 / 切片 / 规格
  - 状态/<枚举>
  - 体量/大       # 方案在已确认及之后：体量/小 或 体量/大
---
```

底图省略 `状态/` 与 `体量/`。

## 同步规则（Agent 必须执行）

1. 改方案进度 / 测试结论 / 切片进度时，同一回合更新对应文的 `状态/*`。
2. `capmap-scheme`：收口升 `已确认` 前完成体量判断+用户确认。
3. `capmap-spec` / `capmap-slice` / `capmap-gate`：见各 skill；大需求路径专用。
4. `capmap-dev`：对照方案判定完成度；底图 §1/§2；方案 → `已开发`；大需求须切片全 `已验收`；**标完必须询问是否转测试**（勿静默结束；用户已点名则可直接 test）；**禁止**因「未自测」卡住已开发；**禁止**本阶段标 `已验证`/`已落地`。
5. `capmap-test`：用户同意转测后拍 1 交测试文（结果可未测）+ 方案 `验证中`；拍 2 人测/免测后 `已验证`。
6. `capmap-norm`：仅方案已 `已验证` 后 → `落地中`→`已落地`。
7. `capmap-archive`：方案 → `已归档`；大需求切片目录随方案进 `_archive`。
8. 底图若出现 `状态/*` → lint error。
9. 违反禁止跳步 / 验证门 / 体量与状态不匹配 / 切片 DAG 规则 → lint error。

## Obsidian 用法

- 筛开发中方案：`tag:#状态/开发中 tag:#方案`
- 筛大体量：`tag:#体量/大 tag:#方案`
- 筛待验收切片：`tag:#状态/待验收 tag:#切片`
- **图谱颜色组**：`capmap-init` 写入 `<docs_root>/.obsidian/graph.json`（见 `capmap-init/assets/obsidian/graph.json`）
