# 状态 Tag（Obsidian）

用于在 Obsidian Tags 面板 / 搜索中**快速筛选**进度。

- **筛「哪些方案在开发/落地」** → 看**方案文**的 `状态/*`（一个方案一个主状态）。
- **能力底图**：只打类型 tag `能力底图`，**禁止** `状态/*`。能力清单仍写在正文 §1 表（策展用），不投影到 YAML Tag。
- **测试文**：`测试中` / `已验证`，与方案主状态可并行（方案可同为 `验证中`）。

## 两轨 + 底图（无状态 Tag）

### A. 方案文档（类型 tag `方案`）— 进度挂这里

```text
方案中 → 已确认 → 开发中 → 已开发 → 验证中 → 已验证 → 落地中 → 已落地 → 已归档
```

| Tag | 含义 |
|-----|------|
| `状态/方案中` | 起草 / 评审 |
| `状态/已确认` | 方向确认，尚未开干或刚开干前 |
| `状态/开发中` | **编码进行中** |
| `状态/已开发` | 代码已合入，§2 已对齐 |
| `状态/验证中` | 测试执行中 |
| `状态/已验证` | 测试通过或明示免测 |
| `状态/落地中` | 规范撰写 / 挂链中 |
| `状态/已落地` | 规范已挂 §3（无需规范时可与已验证合并） |
| `状态/已归档` | 已进 `_archive` |

活跃方案禁止 `已归档`；归档文必须 `已归档`。

### 硬约束：主状态禁止跳步（尤其验证门）

**Agent / 人改 Tag 时必须遵守，capmap-lint 会拦。**

1. **只能沿链条前进或原地微调**，禁止从靠前状态直接跳到靠后状态（例如 `开发中`→`已落地`、`已开发`→`已落地`）。
2. **验证门不可跳过**：进入 `落地中` / `已落地` 之前，方案必须已是 **`已验证`**（或同回合刚从 `验证中` 标为 `已验证`）。
3. **测试未通过禁止落地**：若对应测试文仍为 `状态/测试中`，方案**禁止**标 `落地中` / `已落地`。
4. **免测唯一例外**：用户明示免测时，须在测试文结论写明「免测」范围与日期，并将测试文标为 `已验证` 后，方案才可 `已验证`→后续落地。禁止口头免测、不写测试文就标已落地。
5. 允许的「合并」仅限相邻且语义重合的两步（例如：无独立规范时 `已验证` 可与 `已落地` **同回合**合并，但**仍须先满足已验证条件**）。禁止用「合并」跳过测试。

反例（禁止）：

- 代码写完 → 直接 `已落地`
- 只有单测 smoke、E2E 未做 → `已落地`
- 测试文 `测试中` + 方案 `已落地`

## 文首 YAML

```yaml
---
tags:
  - 方案          # 或 测试 / 能力底图
  - 状态/<方案或测试轨枚举>
---
```

底图省略 `状态/` 行。

## 同步规则（Agent 必须执行）

1. 改方案进度 / 测试结论时，同一回合更新**该方案或测试文**的 `状态/*`。
2. `capmap-dev`：底图 §1/§2 更新；**方案**主状态 → `已开发`（编码中则为 `开发中`）；**不**给底图加状态 Tag；**禁止**在此阶段标 `已落地`。
3. `capmap-test`：测试文 `测试中`→通过则 `已验证`；对应**方案**可标 `验证中`→`已验证`。
4. `capmap-norm`：仅当方案已 **`已验证`** 后，才可标 `落地中`→`已落地`；底图 §3 挂链。
5. `capmap-archive`：方案 → `已归档`（宜在已落地或已验证之后）。
6. 底图若出现 `状态/*` → 视为违规（lint error）。
7. init 空壳底图：`tags: [能力底图]` 即可。
8. 违反「禁止跳步 / 验证门」→ lint error `status_skip`。

## Obsidian 用法

- 筛开发中方案：`tag:#状态/开发中 tag:#方案`
- 筛落地中方案：`tag:#状态/落地中 tag:#方案`
- 底图节点：仅 `tag:#能力底图`（一色即可）
