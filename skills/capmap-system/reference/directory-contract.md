# 文档根目录契约

## 核心原则

**`docs_root` 目录名任意**。在 `capmap-init` 选定并写入 `.agents/skills/capmap-system/capmap.yaml`；之后只认配置。

路径写作 `<docs_root>/...`，执行时替换为真实相对路径。

## 解析顺序

1. 读 `.agents/skills/capmap-system/capmap.yaml` → `docs_root`
2. 若无 → 询问或跑 [capmap-init](../../capmap-init/SKILL.md)
3. 禁止假定一定叫 `docs`

## 目标树（相对 docs_root）

```text
<docs_root>/
├── README.md                 # 可选
├── 文档首页.md
├── 能力总览.md
├── Obsidian使用说明.md       # 可选
├── 方案/
│   ├── 方案索引.md
│   └── <主题>/
│       ├── 能力底图-<可读名>.md
│       ├── <进行中方案>.md
│       └── 切片/                    # 仅体量/大
│           └── <方案stem>/          # 与方案 md 文件名（无扩展名）一致，防多方案冲突
│               ├── <方案stem>-00-规格.md   # 或 00-规格-<短名>.md（须全局唯一）
│               └── <方案stem>-01-<短名>.md
├── 测试/
│   ├── 测试索引.md
│   └── <主题>/
│       └── 测试-<功能可读名>.md
├── 规范/
│   └── 规范索引.md
│   └── <规范标题>.md         # 长期使用/配置/调用
├── 交付/
│   └── 交付说明.md
├── 运维/
│   └── 运维说明.md
└── _archive/
    ├── 归档索引.md
    ├── 方案/<主题>/
    └── 测试/<主题>/          # 可选：过期测试记录
```

## 命名

| 类型 | 规则 |
|------|------|
| 能力底图 | `能力底图-<可读名>.md` |
| 方案 | 标题可读；禁止 README |
| 规格 | `切片/<方案stem>/<方案stem>-00-规格.md`（或等价唯一名；类型 `规格` 可选） |
| 切片 | `切片/<方案stem>/<方案stem>-NN-<短名>.md`（类型 `切片`；**文件名全局唯一**） |
| 测试 | `测试-<功能可读名>.md` |
| 规范 | 标题即契约名（如接入手册、对照表） |

## 能力底图章节

1. 能力清单（含状态：方案中/开发中/已开发/验证中/已验证/落地中/已落地）  
2. 关键代码  
3. 对外契约（**链到规范/**）  
4. 变更轨迹  
5. 已知坑  
6. 考古（方案归档）  
7. （可选）验证与测试（链到 `测试/`）— 也可只在 §3/文末挂测试文档  

文首 YAML：底图仅 `能力底图`，**禁止** `状态/*`；见 [status-tags](status-tags.md)。
