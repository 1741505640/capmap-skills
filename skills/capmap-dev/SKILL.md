# capmap-dev — 开发完成标识

原则：[lifecycle](../capmap-system/reference/lifecycle.md) · Tag：[status-tags](../capmap-system/reference/status-tags.md)

## 完成判定（Agent 可判，不等人测）

对照**方案正文**（范围 / 定案 / 变更记录 / 不做项）与工作区代码，自行判定是否可标 `已开发`：

| 通过条件 | 说明 |
|----------|------|
| 范围落地 | 方案约定的能力点均有对应实现，或方案已写明不做 |
| 路径可指 | 能写出底图 §2 真实路径（文件/模块存在） |
| 体量/大 | `切片/<方案stem>/` 下非规格切片均为 `状态/已验收`；未齐则 **停止**，提示 [capmap-gate](../capmap-gate/SKILL.md) |
| 体量/小 | 无切片要求 |

**禁止用下列理由卡住 `已开发`：**

- 「请先自测 / 测过再说一声」——人测属**验证门**，不是开发完成门  
- 「代码未 push / 未合入主分支」——工作区已落地即可；有 commit/PR 则写入 §4，无则写日期说明  
- 「等用户确认开发完了」——完成度由 Agent 对照方案判定；有缺口则列差额并保持 `开发中`，不要空等  

有缺口 → 列「方案要求 vs 现状」差额，保持 `开发中`，继续补齐或问用户是否砍范围。  
判定通过 → **本回合直接**做完「做什么」1～4，**不要**停成「建议你自测后再标已开发」。

## 做什么

1. 完成判定（见上）；不通过则停止  
2. 打开对应 `能力底图-*.md`：§1 状态列 → **已开发**；§2 补路径；§4 一行轨迹  
3. 底图 YAML：**仅** `能力底图`，去掉任何 `状态/*`  
4. 对应**方案**文主状态 → **`状态/已开发`**（保留体量 Tag）  
5. **交接（必做，禁止静默结束）**：标完 `已开发` 后，在同一回复里**询问**是否转 [capmap-test](../capmap-test/SKILL.md)，例如：  
   > 方案已标 `已开发`。是否现在转测试（写出测试文档并进 `验证中`）？也可以说免测 / 稍后再测。  
   - 用户说转测试 / 写测试 / 继续 → 本回合或下一回合走 capmap-test 拍 1  
   - 用户说免测 → 走 capmap-test 免测路径（测试文结论写明免测 → `已验证`）  
   - 用户说稍后再测 / 先到这 → 保持 `已开发`，记下即可  
   - 用户**本回合已点名**「标已开发并转测试」等 → 不必再问，直接链式 test  
6. **硬约束**：本阶段默认停在 `已开发`（或经用户同意后进 `验证中`）；**禁止**标 `已验证` / `落地中` / `已落地`（`已验证` 须人测结论或明示免测）

## Checklist

```
- [ ] 1. 对照方案完成判定通过（或列出差额后停止）
- [ ] 2. 体量/大 → 切片全已验收（或体量/小跳过）
- [ ] 3. 底图 §1/§2/§4 已更新
- [ ] 4. 底图无 状态/* Tag
- [ ] 5. 方案 Tag = 已开发（禁止已落地）
- [ ] 6. 已询问是否转测试（或用户本回合已点名转测试/免测）——禁止静默结束
- [ ] 7. 未跳过验证门（未自评已验证 / 未进落地）
```

## 不做

- 不把「等人测」当作进入本阶段的前置  
- 不静默停在已开发且不问下一步  
- 不未经询问就自动写测试文（用户已点名转测试除外）  
- 不自评测试通过 → [capmap-test](../capmap-test/SKILL.md)  
- 不写规范 → [capmap-norm](../capmap-norm/SKILL.md)  
- 不归档 → [capmap-archive](../capmap-archive/SKILL.md)  
- 不代替 gate 验收切片
