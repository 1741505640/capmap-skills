# capmap-gate — 切片 frontier / 交票 / 验收

原则：[lifecycle](../capmap-system/reference/lifecycle.md) · [status-tags](../capmap-system/reference/status-tags.md)

## 启动

1. 读 `capmap.yaml` → `docs_root`
2. 定位方案与 `切片/<方案stem>/`（stem = 方案文件名）
3. 方案宜为 `体量/大` 且处于 `已拆分` 或 `开发中`

## 核心概念

| 词 | 含义 |
|----|------|
| **frontier** | 该方案切片目录内：全部 Blocked by 切片均为 `已验收`（或无依赖），且自身为 `待开发` 的集合 |
| **点名** | 用户明确「开 01」「并行开 02 和 03」等；未点名不得开跑 |
| **交票** | Agent 写入 Demo 步骤 + 自测摘要 + **可目检产物** 后标 `待验收` |
| **可目检产物** | 人能**直接打开看/听**的文件（mp4/png/wav/日志），不是数字、不是断言、不是"我测过了" |

## 交票必备：可目检产物（写进切片文档）

> **数字证明我没算错，证明不了你看到的效果。** 凡是"人能看出来/听出来"的判据，
> 交票时必须留下可看/可听的产物 —— 否则等于要用户凭信，用户只能反复问
> 「结果在哪、我怎么目检」。

**每次交票都要在切片文档内写全这四项**，缺一不得标 `待验收`：

1. **产物清单**：文件路径（写死，便于直接打开）+ 每个产物对应哪条判据
2. **生成命令**：一条能重跑出全部产物的命令（脚本化，禁止手工临时产物）
3. **人工验收步骤**：打开哪个文件、**应该看到/听到什么**（通过标准）
4. **反例含义**：不通过时说明是「没生效」还是「参数要调」，便于人定位

纪律：

- **凡是"效果类"判据（视觉/听觉/交互），禁止只给数字**：帧数、SSIM、LUFS 是辅证，不是产物
- 产物要**可重复生成**：写成脚本（如 `scripts/demo_NN_evidence.py`）并落固定目录
- 反差类判据要给**对照**：如"修复前 vs 修复后"两个文件并排，或素材本身一并给出
- 让差异**自己说话**：能用带计时器/水印/可标注的素材就别用纯色块（例：段长是否被截短，用带计时器的测试图案，肉眼直接可判）
- 产物目录**按切片/主题分目录**，生成脚本**只清自己那一个目录**；
  **禁止** `rmtree` 共享产物根目录（会把其它切片的产物一起删掉）
- 产物路径要在**切片文档**与本回合回复里**都**给出；被 gitignore 的目录要说明怎么重新生成

> 判据本身写在切片文的 `## 验收判据`（机器已验证 / 只有人能判），
> 产物与验收步骤写在 `## 可目检产物`，两者一一对应。

## 硬规则

1. **只**处理当前方案 `切片/<方案stem>/` 下的切片（不要串到其他方案）
2. 未点名：只展示 frontier、触及冲突提示、推荐运行模式 → **停住**
3. 点名后：校验目标 ⊆ frontier；触及重叠不得同时 `开发中`；合法则标 `开发中`；方案若仍为 `已拆分` 可改为 `开发中`
4. **禁止**领取非 frontier；**禁止** Agent 主动开跑或 spawn
5. 交票 → `待验收`：切片文必须有 **Demo 步骤**、**自测摘要**、**可目检产物**（产物清单 + 生成命令 + 人工验收步骤 + 反例含义）；缺则不得标待验收
6. `待验收` → `已验收`：**仅人确认**（如「通过」「验收完成」）；Agent 不得自评
7. 验收后重算 frontier 并展示；仍不自动开下一张
8. 全部切片 `已验收` 后：走 [capmap-dev](../capmap-dev/SKILL.md)；标完已开发后询问是否转测试；未齐时勿标方案已开发
9. 切片验收 ≠ 功能验证；整功能仍走 [capmap-test](../capmap-test/SKILL.md)（经用户确认转测后）
10. **禁止把验证产物删掉/覆盖**：产物是验收依据；清理脚本必须先确认不误伤既有产物（含其它切片的）

## 动作速查

| 用户意图 | 行为 |
|----------|------|
| 看 frontier / 能开啥 | 列出 frontier + 推荐；停住 |
| 开某张 / 并行开这些 | 校验后标开发中；开始该切片工作（本窗一张） |
| 交票 / 做完了 | 写 Demo+自测+可目检产物 → 待验收；**给出产物路径与验收步骤**；等人 |
| 验收通过 | 已验收 → 重算 frontier → 展示；停住 |
| 「结果在哪 / 我怎么目检」 | **这是交票不合格的信号**：补产物或补产物清单，别只重述数字 |

## Checklist

```
- [ ] 1. 解析方案 stem 与切片目录
- [ ] 2. 计算 frontier；检查触及冲突
- [ ] 3. 无点名 → 展示后停住
- [ ] 4. 有点名 → 合法开干（开发中）
- [ ] 5. 交票材料齐全（Demo + 自测摘要 + 可目检产物四项）→ 待验收
- [ ] 6. 回复里给出产物路径 + 每条判据"应该看到什么"
- [ ] 7. 人确认 → 已验收 → 重算 frontier
```

## 不做

- 不拆新切片清单（大改拆分）→ [capmap-slice](../capmap-slice/SKILL.md)
- 不写功能测试文档 → [capmap-test](../capmap-test/SKILL.md)
